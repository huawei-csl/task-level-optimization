# Benchmarks

Six design tasks, each released as four folders under `benchmarks/`:

| folder | contents |
|---|---|
| `<bench>_spire` | Spire starting design (`context/starting_point.py`), task-level testbench `tb.sv`, `vectors.dat`, `description.txt` (the agent's task text), `metadata.json` |
| `<bench>_verilog` | the same with a Verilog starting design; `tb.sv` and `vectors.dat` are byte-identical to the Spire folder |
| `<bench>_<hdl>_equiv` | generated by `python -m tasklevel.variants`: same start and vectors, testbench replaced by the trace oracle (`trace.dat`/`trace_len.dat`, or `lat.dat` for the ALU) captured from the start |

The folder name is the benchmark name the engine sees (`metadata.json: name`). The harness copies
`context/` flat into the agent's workspace, which is why descriptions cite `starting_point.py`
without a path.

| key | folder stem | interface | workload | task-level oracle | origin |
|---|---|---|---|---|---|
| `matmul` | `matmul_16x16x16_1r1w` | 1R/1W 16-bit memory port; A, B in, C out | 16x16x16 integer matrix products, several cases | result matrix in memory | own design |
| `jpeg` | `jpeg_idct_2d_1r1w` | 1R/1W memory port; 8x8 coefficient blocks in, pixels out | 323 blocks | output pixels | ultraembedded/core_jpeg 2-D IDCT |
| `cv32` | `cv32e40p_alu_divh` | the CV32E40P ALU handshake (`enable_i`/`ex_ready_i`), division-heavy operation mix | the ALU's instruction stream | `result_o`, `comparison_result_o` per operation | OpenHW Group CV32E40P |
| `qr8` | `qr8_1r1w` | 1R/1W memory port; 8x8 matrix in, R out | fixed-point CORDIC Givens QR, 15 job classes | R matrix in memory | Zero ASIC LogikBench `qr` |
| `ofdm_tx` | `ofdm32_mod_1r1w` | 1R/1W memory port; payload bits in, time-domain symbol out | 32-carrier OFDM, 21 jobs | 40 complex samples per job | LogikBench `ofdm` tx half + `fft` |
| `ofdm_rx` | `ofdm32_demod_1r1w` | 1R/1W memory port; noisy samples in, bits out | 21 jobs, below-threshold channel noise | recovered payload bits | LogikBench `ofdm` rx half + `fft` |

The memory-port benchmarks count cycles, reads and writes (`TB_CYCLES`, `TB_READS`, `TB_WRITES`),
which the movement objectives and the uniform rescore use; the ALU benchmark counts cycles.

## Starting designs and HDL twins

The Spire starts are the ones the paper's main experiment optimizes; the Verilog starts repeat
the experiment with the other RTL representation (Appendix "Independence from the RTL
representation"). For jpeg, qr8 and the ofdm halves the Verilog start is the upstream Verilog
behind the study interface with every edit marked `// RTLScout:`; cv32 is a flattened copy of the
upstream ALU files; matmul is our own design in both HDLs. Where the flow's lack of buffering
made a shared register with ~1k fan-out dominate the Verilog start's period, the register is
replicated per consumer (marked), the same fix applied to the upstream measurement benchmarks.
Both starts of a benchmark measure the same cycles and, within the flow's noise, the same area
and period.

## Upstream measurement benchmarks

`benchmarks/upstream/<name>/` holds five designs at their native interfaces (verbatim upstream
RTL, marked one-line edits only) with a testbench that replays the study workload and counts
cycles. They are measurement vehicles for `python -m tasklevel.upstream` (the paper's upstream
comparison), not agent targets. Provenance and licenses: `THIRD_PARTY_LICENSES.md`.

## Validation testbenches

`validation/<bench>/tb_v2*.sv` are independent second testbenches (directed corner cases plus more
than a million random stimuli) that the agent never sees. Their stimulus/golden files are large
and regenerated deterministically by the generators next to them (`python -m tasklevel.validate
--regen`), with SHA-256 hashes in `validation/vector_hashes.json`. Goldens come from the upstream
RTL simulated by the generator (qr8, ofdm), from the bit-exact Spire start in `+capture` mode
(jpeg, cv32) or from an exact in-testbench model (matmul).
